# 国际化与多语言

[返回运维与开发概览](/yunzai/docs/operator/index) | [配置说明](/yunzai/docs/operator/configuration) | [运行与日常维护](/yunzai/docs/operator/operations) | [开发指南](/yunzai/docs/operator/development) | [插件开发](/yunzai/docs/operator/plugins)

本项目仅内置简体中文（`zh-CN`）默认文案，不预置英文或其他外语语言包。主人可以通过管理面板修改默认文案、放入自行编写的额外语言文件并切换语言；开发者可以使用校验脚本维护各单元的默认词库。

## 日常使用：修改文案与切换语言

文案体系将随代码发布的默认词库（各单元的 `i18n/zh-CN.json`）与用户私有配置（`config/i18n/`）分开存放。`config/i18n/` 目录在首次修改文案或切换语言前可能不存在，保存时会自动创建，不会改动 Git 跟踪的默认 `i18n/zh-CN.json`。

### 通过管理面板修改文案

在管理面板中可以查看各命名空间的默认文案、功能分段说明与参数说明，并直接编辑保存：

- 编辑结果会写入 `config/i18n/<tag>.json`（例如 `config/i18n/zh-CN.json`）。
- 只能修改默认词库中已有的 `namespace` 与 `key`，不能在面板中新增未定义的键。

### 放入额外语言文件

如需使用简体中文以外的语言，需由用户自行编写 JSON 文件并放入以下任一目录：

- `i18n/languages/<tag>.json`
- `config/i18n/<tag>.json`

文件要求如下：

- 文件名去除 `.json` 后作为语言标签（例如 `en-US.json`），下划线 `_` 会被规范化为 `-`。`settings.json` 为系统保留文件名，不作为词库读取。
- 单个语言文件不超过 16 MiB，且所在目录与文件本身不能为符号链接。
- JSON 结构支持 `name`（可选，语言列表中展示的名称，不超过 160 字符）、`language`（可选，填写时需与文件名标签一致）和 `messages`（必填，两层对象 `{ "<namespace>": { "<existing_key>": "<译文>" } }`）。
- 额外语言文件只能覆盖默认词库中已有的 `namespace` 与 `key`，存在未知命名空间或未知键时会被拒绝。

下面是一个可直接复制使用的自定义语言文件示例（以用户自行编写的英文示例文件为例，项目本身不预置该文件）：

```json
{
  "name": "English (Custom)",
  "language": "en-US",
  "messages": {
    "system": {
      "index.text_47ea7e256d": "帮助文档：\n{helpUrl}"
    }
  }
}
```

示例中的 `system` 为现有命名空间，`index.text_47ea7e256d` 为真实存在的文案键，`{helpUrl}` 为必须保留的占位符。实际翻译时将文案内容替换为目标语言即可。

### 切换语言与重启生效

放入额外语言文件后，在管理面板中选择目标语言即可切换，当前选择会写入 `config/i18n/settings.json`。

同一语言标签存在多处定义时，按私有覆盖优先的顺序逐命名空间、逐键合并（优先级从高到低）：

1. `config/i18n/<tag>.json`（面板编辑产物或用户私有覆盖）
2. `i18n/languages/<tag>.json`（基础额外语言文件）
3. 各单元的 `i18n/zh-CN.json`（默认简体中文；当前语言缺少某个键时自动回退到此项）

项目不承诺所有文案修改都能完全热更新。部分模块的顶层菜单标题或静态标签在进程启动时读取并固定。当管理面板返回 `restartRequired` 为 `true`，或手工修改了 `config/i18n/*.json`、`i18n/languages/*.json` 后，请按 [运行与日常维护](/yunzai/docs/operator/operations) 中的方式重启服务进程。

## 默认中文 Catalog 结构与命名空间

各单元的 `i18n/zh-CN.json` 既是运行时加载的默认文案源，也是管理面板展示文案用途与参数说明的元数据来源。

### 默认命名空间映射

启动加载时，[`lib/i18n-settings.ts`](https://github.com/MOPELotus/Lotus-Yunzai/blob/main/lib/i18n-settings.ts) 按以下路径映射默认 `namespace`（若文件内显式指定了合法的 `namespace` 且包含 `messages` 字段，则以文件内声明为准）：

| 默认词库路径 | 默认 `namespace` |
| --- | --- |
| `i18n/zh-CN.json` | `core` |
| `i18n/<子目录>/zh-CN.json`（排除 `i18n/languages`） | `<子目录>` |
| `packages/<包名>/i18n/zh-CN.json` | `<包名>` |
| `plugins/<插件名>/i18n/zh-CN.json` | `<插件名>` |
| `panel/i18n/zh-CN.json` | `panel` |

### Catalog 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `language` | 字符串 | 固定为 `"zh-CN"`。 |
| `name` | 字符串 | 可选；仅 `core` 单元中的 `name` 用作默认简体中文的显示名称。 |
| `namespace` | 字符串 | 可选；指定当前词库的命名空间，缺省时按目录名映射。 |
| `description` | 字符串 | 当前单元文案的整体用途说明。 |
| `sections` | 对象 | 按功能区块说明文案用途，键为前缀，值包含 `description`（功能说明）与 `source`（对应源码相对路径）。 |
| `parameters` | 对象 | 记录各文案键使用的占位符及含义说明。 |
| `messages` | 对象 | 实际的文案键值对字典。 |

`messages` 中的每个键都必须在 `sections` 中匹配到对应前缀（`key === section` 或 `key.startsWith(section + ".")`），且该分段需具备非空的 `description` 和 `source`。

### 占位符与编辑边界

[`packages/i18n/index.ts`](https://github.com/MOPELotus/Lotus-Yunzai/blob/main/packages/i18n/index.ts) 中的 `formatMessage` 函数按 `{参数名}` 形式识别占位符，运行时仅做单次替换（参数值本身包含 `{...}` 不会被二次解析），未传入对应参数时原样保留。修改文案时不要改写或删除 `parameters` 中列出的 `{占位符}` 键名。

调整或翻译文案时，应保留以下功能性标识的原貌，不要当作普通自然语言句子改写：

- 内部路径、文件路径与 URL。
- 用户交互命令、指令前缀与功能选择器。
- 协议错误码、状态码与结构化输出键名。
- 内嵌脚本或 Lua 代码片段、短技术标签。

## 开发者词库校验脚本

开发插件或修改核心代码时，使用 [`scripts/i18n/check.ts`](https://github.com/MOPELotus/Lotus-Yunzai/blob/main/scripts/i18n/check.ts) 对受管单元的 `i18n/zh-CN.json` 执行完整性校验：

```bash
# 全量校验所有单元
bun scripts/i18n/check.ts

# 仅校验单个单元（例如 panel 或 plugins/genshin）
bun scripts/i18n/check.ts --unit=panel
bun scripts/i18n/check.ts --unit=plugins/genshin

# 清理未使用的自动生成条目
bun scripts/i18n/check.ts --prune
```

`--prune` 仅会删除源码中已无引用且键名符合 `*.text_<10位十六进制>` 规则的自动生成条目，以及随之变空的 `sections` 分段，不会删除人工命名的语义键。

校验范围包括根目录 `.`（仅扫描 `app.ts`、`lib/`、`scripts/`、`web/`）、`panel`、`plugins/` 下的各内置插件以及 `packages/` 下的相关基础包。脚本会检查 `language`、`description`、`sections`、`parameters`、`messages` 是否完整，源码中通过 `$t*("key")` 或 `panelText("key")` 调用的键是否已登记，以及 `parameters` 中声明的参数是否都包含在对应文案的 `{name}` 占位符中。
